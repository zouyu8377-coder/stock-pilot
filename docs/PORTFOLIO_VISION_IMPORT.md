# 账户截图识别

版本：`portfolio_vision.minimax.v2`

## 正式流程

1. 用户选择“当前持仓截图”或“交易行为截图”，再点击或拖拽上传图片。
2. 用户明确勾选云端发送授权后，前端才允许提交。
3. 火山引擎 `minimax-m3` 按截图类型分别提取持仓或成交字段。
4. 后端对白名单字段、持仓行数和 warning 长度进行确定性裁剪。
5. 本地证券库匹配代码，并校验数量、可用数量、成本、截图价格和市值。
6. 前端展示可编辑草稿及相对上一快照的建仓、加仓、减仓、清仓变化。
7. 用户确认后才保存正式组合快照；旧快照继续保留。

## 交易截图

- 成交字段包括证券名称、买卖方向、成交均价、成交量、成交额和可见成交时间。
- 本地系统校验 `成交均价 × 成交量 ≈ 成交额`，并完成证券代码标准化。
- 所有确认成交都进入独立交易台账，用于后续复盘。
- “仅记录交易”不会修改持仓，适用于当前持仓截图已经包含这些成交的情况。
- “记录并更新持仓”会更新数量和现金；买入按成交额计算加权成本，卖出按已收回资金摊薄剩余持仓成本，因此高位减持后成本可以为零或负数。
- 零或负摊薄成本仍保留盈亏金额口径，但不计算收益率百分比，避免负分母产生误导。
- 卖出数量超过当前持仓时，系统阻止应用并建议“仅记录交易”，避免重复扣减。
- 手续费、印花税和其他费用未在图片展示时不进行推测，因此现金变化按成交额计算。

## 模型约束

- 正式模型：`minimax-m3`
- 单次最大输出：`4096` token
- 温度：`0`
- JSON mode：开启
- 持仓行上限：`80`
- 行级 warning 上限：`2`
- 总体 warning 上限：`4`
- `finish_reason=length` 时拒绝不完整结果，不创建可确认持仓行。

模型响应只作为草稿来源。证券代码标准化、数值交叉校验、快照差异和正式保存均由本地系统负责。
