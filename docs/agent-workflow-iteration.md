# 统一决策流程（2026-09-07）

## 本轮交付

驾驶舱以“巡检并分析”为主入口。后台任务按顺序完成：

1. 巡检取证：记录账户变化，重建覆盖缺口，执行预算内已有工具任务。
2. 综合分析：刷新上下文，把本次工具证据一并交给模型，生成一份新分析。
3. 形成建议：保存结果、同步核查待办、刷新驾驶舱。条件性增减持建议必须有引用、触发条件、观察周期及失效条件。
4. 回顾历史表现：更新已到评价窗口的历史操作和建议表现；详细内容在“复盘与记录”。这一步不是额外调用一次复盘模型。

API：POST `/api/agent/review/workflow` 返回202及任务ID；GET同路径查询最近一次任务。重复点击复用正在运行的任务，失败保留原有分析，重启后将未完成任务标为中断。不自动恢复未完成的模型调用。

页面默认只展开三项主要建议和方向机会。取证明细、实时规则评分及重点持仓规则明细折叠。规则巡检和模型分析明确区分，旧分析保留完成时间，不冒充新结果。

## 可靠性修正

- 公告“已发现”与“已处理”分开。未读、下载失败、模型失败不再随索引刷新被永久跳过；旧缓存只迁移实际文档记录。分批处理上限不变，失败项在下一批让位于未尝试文档。
- 公告工具主动核验正文；仅有索引或没有有效方向性引用时标为部分完成。
- 缺失MA20、价格、相对强度、5日涨跌及陈旧行情不形成已确认机会。潜在机会需要量能门槛，过热不列入低追高风险机会。
- 收益路径评价不再声称验证了Thesis；没有显式因果核验标记的价格样本不能激活因果学习规则。
- 所有复盘生成函数共用模型分析互斥锁，旧请求超时后后台尚未结束时不能再并发生成。
- 已启用的晨间巡检不再以“已有待办”为前提。08:45后启动可以补检，15:30后不补晨检；有交易才触发收盘操作复盘的规则保持不变。
- 后台轮询的取数或判定异常不再直接终止整个循环。

## 明确保留的边界

- 尚不是开放网络研究Agent：只调用现有白名单工具，未新增新闻检索、宏观结果与商品行情连接器。
- 自动巡检目前仍需存在初始分析；首次使用需手动点击主入口。规则巡检不保证每天调用模型。
- 调度仍依赖本机后端运行，工作日判断尚未升级为交易所节假日日历；独立通知渠道也未加入。
- 新入口沿用自动化分析次数上限；旧手动复盘与公告核验费用尚未纳入一个统一的全局token账本。
- 当前使用单进程线程和本地任务状态，未实现多worker分布式锁。停止服务会中断任务。
- 旧分析不会被自动重写。新条件性建议字段在下一次成功生成后生效。
- 模型输出中的条件性建议只供用户确认，不执行交易，不承诺收益。

## 下一阶段

优先统一交易日历和总预算账本，再增加可审计的信息源适配器及通知。新的学习规则应有事实验证、用户审核与回滚机制；不能仅因短期涨跌调整长期投资逻辑。
