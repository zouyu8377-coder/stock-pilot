# 决策工作台：三项改进

## 首页

- 账户状态优先显示账户盈亏、仓位、现金和最大主方向暴露，不再并排展示三套分数。
- 公告反证、仓位超限和现金不足优先进入待处理事项，不能被其他评分抵消。
- 数据缺失时标为证据不足，不认定账户安全；仅有账户浮盈不能覆盖总账户亏损。
- 待处理事项最多展开三项，潜在机会最多三项。其他明细、原始证据及底层评分统一折叠。
- 非今日AI结果明确标为历史分析，不展示为当日增减持建议。
- 方向时效暂按最近已收盘工作日保守过滤；交易所节假日日历仍待统一。

## 任务运行

自动巡检、手动分析、操作复盘和手动工具执行共用轻量任务状态。GET `/api/agent/review/workflow` 提供当前来源、阶段、对象、已完成/总项数、开始及最近进展时间、已用时、模型请求数、已返回token及错误。

运行中点击主按钮仅查看已有任务。POST `/api/agent/review/workflow/cancel` 取消后续步骤，正在执行的供应商请求等待返回或超时后停止，不声称可撤回已发送请求或费用。取消/超时检查发生在步骤边界和结果发布前。

- 模型HTTP隐式重试关闭。长度耗尽不再重复同参数调用；一般JSON校验问题最多修正一次。
- 分析开始前登记请求尝试，失败请求占用分析任务预算。状态中token只统计已经收到的usage，不估计超时请求费用。
- 自动失败最早15分钟后重试，同来源当日失败两次停止自动重试；用户取消后当日不自动重启同来源。
- 阶段超过期限会提示等待异常；步骤返回后停止后续工作。总任务软时限15分钟，不能强制终止任意阻塞线程。
- 进程重启会记录中断，已登记的模型请求不会因重启而从预算中消失。
- 手动重新巡检复用有效工具结果，但重新构建上下文，不盲目续接过期的模型输入。

上述预算覆盖统一任务中的分析/取证模型请求；独立截图识别和独立公告后台刷新尚未统一为全平台费用账本。仍以单进程后端运行，未实现分布式任务队列。

## 建议校验

模型输入新增每个标的的账户约束；输出补充目标代码、账户影响、触发条件和期限。

增持必须存在可确认的单票、主题和现金余量；缺失、余量耗尽、执行受阻、重大风险队列、低置信度或缺少条件时降级为核查。减持必须关联当前持有标的。相同标的同时出现机会与风险/待核查判断时，优先核查，不并列给出冲突的增持建议。

底层分数保留作为排序参考，不视为行业标准或收益概率。默认没有改变用户模型、深度思考模式或提高token上限，后续按用户选择验证模型请求参数。
