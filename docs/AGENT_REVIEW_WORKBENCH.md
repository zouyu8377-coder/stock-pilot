# Stock-Pilot 复盘任务工作台

版本：`agent_task.v2`

## 工作流

1. 用户主动生成 AI 复盘，或由每日 15:30 自动循环触发。
2. 后端将带有标的、证据类型、缺口和完成标准的 `verification_tasks` 转换为有状态核查任务。
3. 确定性映射器解析证券代码与已知名称，只允许调用白名单工具。
4. 工具结果保存为 `tool:{task_id}` 证据，不直接修改模型结论。
5. 自动循环或用户主动选择“核查并更新复盘”后，新增工具证据才会发送给已配置模型。
6. 新复盘通过证据编号、陈旧数据和交易指令校验后成为最新版本。
7. 到期建议与已确认交易由确定性规则评价，压缩后的成功/失败模式进入下一次 DeepSeek 上下文。

## 任务状态

- `pending`：等待自动执行。
- `running`：白名单工具正在执行。
- `completed`：工具结果已保存为证据。
- `partial`：已取得部分证据，但仍存在明确的数据缺口。
- `failed`：执行失败，可重试并保留错误。
- `retry_wait`：临时数据源错误，按指数退避等待自动重试。
- `superseded`：相同核查目标已被新复盘接管，旧任务保留审计记录但不再执行。
- `manual_required`：无法由白名单工具可靠完成。
- `dismissed`：用户明确忽略。

## 白名单工具

- `stock_snapshot`：读取指定证券的实时行情和本地历史行情摘要。
- `rotation_refresh`：重建轮动缓存，不绕过底层冷数据新鲜度边界。
- `event_snapshot`：读取当前重要事件及其组合影响。
- `disclosure_snapshot`：读取指定证券的公告、调研索引和已校验的 Thesis 证据。
- `manual_review`：仅作为人工任务标记，不能自动执行。

## API

- `GET /api/agent/review/tasks`
- `POST /api/agent/review/tasks/{task_id}/execute`
- `PATCH /api/agent/review/tasks/{task_id}/status`
- `POST /api/agent/review/tasks/execute-pending`
- `POST /api/agent/review/cycle`

`/cycle` 会先执行当前复盘的待处理白名单任务，再使用成功结果生成后续复盘。任何接口都不会执行交易或修改真实持仓。

## 自动循环与结果评价

- 自动循环由用户在前端启用，默认每个工作日 15:31 检查当日已确认操作记录。
- 当日存在经用户确认的成交记录或持仓数量变化时，收盘复盘必定执行；手动复盘不会抑制本次计划任务。
- 当日没有新增交易操作时不自动触发，调度成功后才记录当天已完成，失败时保留重试机会。
- 每轮先记录组合变化并评价到期结果，再按预算生成复盘、执行核查工具，并在取得新证据时完成同轮二次复盘。
- 默认每日最多调用模型 2 次，对应初次复盘和基于新增证据的复核。
- 第二次复盘如产生新的白名单核查任务，会继续执行工具；新证据留待下一次复盘吸收，避免突破模型预算。
- 中断超过 15 分钟的运行中任务会恢复为待执行；临时源错误最多尝试 3 次，无效任务不反复调用。
- 建议结果由固定行情阈值评价为 `supported`、`not_supported`、`mixed` 或 `insufficient`。
- 经用户确认的持仓截图差异直接成为正式操作样本；其他系统快照推断仍为候选，需人工确认。
- 成交截图经用户确认后直接进入正式交易台账，并冻结操作时点可见的 AI 策略。
- 自动循环不会提交交易、修改持仓或突破模型调用预算。

## 建议生命周期与月报

- 每条新建议冻结生成时的模型、行动语义、失效条件及被引用证据，后续行情更新不会覆盖原始判断依据。
- 生命周期记录 `proposed`、`open/tracking`、`evaluated` 等状态及状态变化时间。
- 到期评价同时计算标的绝对收益、最大回撤和相对沪深300ETF（`510300`）的超额收益。
- 规则归因使用方向判断、时点或阈值、风险遗漏、信号未兑现等固定类别，不由提出建议的模型自评。
- 月报只将用户确认过的调仓纳入正式成绩；未确认的快照推断仅显示为待清理数据。
- 评价除支持/不支持外，还记录方向准确性、时点质量、风险控制价值与原假设有效性。
- 每次复盘输出“相比上一版”和最多三项“今日决策焦点”；无显著变化时允许明确输出“无需行动”。
- `GET /api/agent/review/outcomes/monthly?month=YYYY-MM` 返回规则化月度成绩单。

## 用户操作闭环

- 每次确认持仓截图后，记录与上一快照之间的账户资产、现金、逆回购、持仓数量、
  摊薄成本和截图市值变化。即使持仓数量未变化，也保留快照事件。
- 每次确认交易截图后，记录买卖方向、成交均价、成交量、成交额和是否已应用到持仓。
- 对发生数量变化的用户操作，冻结操作时点之前已经存在的 AI 建议，标记为
  `aligned`、`conflicted`、`mixed` 或 `no_direct_recommendation`；操作之后生成的建议不得倒灌。
- 观察期结束后，固定规则同时评价操作收益、相对沪深300的超额表现和与原建议的关系，
  形成“建议一致且得到支持”“一致但未得到支持”“逆向操作得到支持”等策略反馈。
- 操作反馈进入下一次 `learning_feedback`，驱动新的核查计划。模型只能解释冲突和规划取证，
  不能修改历史事实或充当原始事实来源。

## 闭环健康指标

- `strategy_context_coverage_pct`：已确认操作中，冻结了操作时点策略上下文的比例。
- `direct_strategy_match_rate_pct`：已确认操作中，找到标的级直接建议的比例。
- `matured_evaluation_rate_pct`：已确认操作中，达到观察周期并完成评价的比例。
- 未到观察周期的操作不会被计为评价失败。
