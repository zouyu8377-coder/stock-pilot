## Scope

This round did not build a dashboard page, did not add account-level AI calls, did not add OCR/cloud vision/screenshot import flow, did not add new data sources, did not add position/theme/cash/repo decision thresholds, and did not generate buy/sell/action advice.

## Root Causes And Fixes

1. Valuation mix happened in `PortfolioService.compute_metrics`: enriched market value used current system quotes while `snapshot.total_assets` could remain a saved snapshot value. The fix makes `PortfolioMetrics.total_assets` and all current weights use `current_quote_total_assets = total_market_value + cash_available + repo_amount`, while retaining `snapshot_total_assets` for saved-account context.

2. `AI_PCB` related observation over-inclusion happened in `PortfolioService.compute_metrics` through `THEME_GROUPS`, where `AI_PCB` grouped both `AI_PCB` and `AI_THEME_ETF`. The fix removes grouped risk tags and aggregates related observations strictly from confirmed `theme_tags`.

3. Confirmed `observation` role was treated as missing in `build_portfolio_packet`. The fix adds role-state helpers: empty/unclassified roles are gaps; `observation` is a gap only when it is not user-confirmed.

4. Old AI questions were generated by `PORTFOLIO_LLM_QUESTIONS` in `packet_service.py`. The fix replaces concentration/cash/trade-discipline questions with descriptive evidence-organization questions.

## Valuation Basis

Portfolio Packet `account_overview` now contains:

- `snapshot_valuation`: saved-account values at snapshot time.
- `current_quote_estimate`: current enriched holding market value plus cash/repo carried from the saved snapshot.
- `valuation_basis = current_quote_estimate`.

The current display-compatible legacy fields (`total_assets`, `total_position_weight`, `cash_weight`, `repo_weight`) now use the current quote estimate denominator. The snapshot total remains available as `snapshot_valuation.snapshot_total_assets`.

## Theme Observations

Official exposure still uses only confirmed `primary_theme` and remains additive. Related observations now use confirmed `theme_tags` exactly:

- `AI_PCB` contains only holdings with confirmed `AI_PCB`.
- `AI_THEME_ETF` contains only holdings with confirmed `AI_THEME_ETF`.
- `HIGH_VOLATILITY` remains a descriptive tag observation when user confirmed.

No `AI_RELATED` tag was added in this round. It remains a possible future semantic suggestion, requiring explicit user confirmation before it can enter confirmed `theme_tags`.

## Role Semantics

User-confirmed `observation` is now a valid role. It is represented as an observation role and is not inferred into `core`, `trend`, `defensive`, or `short_term`.

## AI Context Boundary

Portfolio Packet and AccountAnalysisContext now include inactive decision rules:

- `single_position_limit`
- `primary_theme_limit`
- `cash_floor`
- `repo_cash_equivalent_policy`

The AI boundary states that the context is only for account fact summary, theme structure observation, shared external-driver organization, and data-gap identification. Disabled position, cash, and repo rules must not be used as action or discipline-violation grounds.

Default questions now ask for official theme summaries, non-additive tag boundaries, shared external-driver context, missing information, and separation between context/assumptions and verified facts. They do not ask whether the portfolio is overly concentrated, whether cash/repo optionality is enough, or whether a proposed trade changes inactive discipline rules.

## External Driver Context

The detailed Portfolio Packet keeps the audit-oriented external driver summary. AccountAnalysisContext now uses a compact structure:

- `shared_external_driver_observations`
- factor id, display name, associated symbols, data status, reason
- boundary that external drivers are contextual and not causal or trading conclusions

It does not repeat full mapping payloads, retrieval configs, or evidence bodies.
