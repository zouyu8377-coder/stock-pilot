# 外部讨论闭环

工作台主入口改为“讨论资料 → 外部讨论 → 结果预览 → 用户确认”。
旧模型分析、计划管理的文件与历史保留，不再作为首页的并列操作入口。

## 文件与版本

固定目录：`backend/data/external_discussion/current/`。

- `prompt.md`：问题、完整数据和最终 JSON Schema。先讨论，结束后才回传。
- `context.json`：账户、证据目录、已有记录与旧版记忆。
- `manifest.json`：讨论 ID、版本、上下文指纹、账户指纹与生成时间（+08:00）。
- `response.json`：外部模型最终结果，原子写入；也可在同一入口粘贴。
- `validation.json`：校验结果、变更预览或修正提示。
- `supplement.json`：外部模型提出的受限数据补充请求，用户点击执行。
- `received/`：已识别的有效格式回传备份，以内容哈希命名，重复不新增。

默认继续当前讨论，不重复取数、不散落导出文件。需要最新行情时选择
“刷新资料并继续”；新问题可选择“新建讨论”。刷新/新建前按月份归档旧版。
未确认的讨论新建前需显式允许归档。投资历史不自动清理。

## 回传边界

结果中的 changes 为显式 add/update/retract，支持账户、方向、标的三级的
判断、建议、待办、记忆。每项包含依据、信心及原因、触发与失效条件。
空数组不会删除已有内容。确认后只写讨论记录，不修改持仓或交易流水。

导入检查版本、证据编号、账户变化、记录版本、结果 ID 和预览内容哈希。
同版本只允许确认一份结果。多个模型的不同结果不能由粘贴入口静默覆盖；
本地文件在被识别后会保存内容哈希备份。用户仍需确认当前文件对应的预览。
结构通过不代表投资判断正确；新增外部来源明确标记为未经本地核验。

网页打开时约每5秒检查回传；网页关闭或后台隐藏时不持续轮询。
应用关闭时外部文件仍可写入，下次打开工作台接收。没有调用内置模型。
补充任务限 market/disclosure/events、最多5个代码，不允许模型指定URL、
执行脚本、任意路径或交易。资料补充会提升版本，需要重新阅读上下文。
