# Stock-Pilot 火山引擎候选模型评测

评测日期：2026-07-29

候选模型：

- `minimax-m3`
- `glm-5.2`
- `deepseek-v4-pro`
- `kimi-k2.7-code`

## 结论

`deepseek-v4-pro` 可以胜任 Stock-Pilot 第一版“复盘推理大脑”，前提是由
Stock-Pilot 后端提前组装好账户、轮动、事件和个股上下文，模型主要负责证据综合、
风险审计和机会阶段解释。

当前四个模型均不适合直接承担完全自主的工具编排。SP-11 要求只调用一次
`get_stock_context(512480)`：

- GLM 调用了所需工具，但额外调用了不必要的轮动工具；
- MiniMax 调用了所需工具，也额外调用了轮动工具；
- DeepSeek 和 Kimi 没有执行工具调用，而是停在“证据不足”。

因此第一版推荐采用“确定性编排 + 模型推理”，而不是让模型自由决定所有数据调用。

## 标准化结果

统一条件：13题、每题一次、相同 system prompt、相同数据、相同 JSON 契约、
`max_tokens=2500`。总分130分。结构化输出失败属于 hard fail，该题最高3分。

| 模型 | 客观分 | 合法结构 | Hard fail | 平均延迟 | 总 token | 判断 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| deepseek-v4-pro | 118.0 | 13/13 | 0 | 20.3秒 | 20,214 | 第一版首选 |
| kimi-k2.7-code | 105.5 | 12/13 | 1 | 60.5秒 | 30,215 | 深度复核/第二意见 |
| glm-5.2 | 72.5 | 8/13 | 5 | 36.8秒 | 35,533 | 能力可用，但默认预算下不稳定 |
| minimax-m3 | 39.5 | 4/13 | 9 | 26.8秒 | 39,220 | 不适合作为默认大脑 |

客观分检查结构、证据引用、预期结论类型/置信度、行动边界、核查任务和表达完整性；
最终判断还结合了逐题人工语义审查。

## 高预算诊断

只对首轮结构失败题使用 `max_tokens=5000` 重测，不覆盖首轮成绩：

| 模型 | 重测结果 | 说明 |
| --- | --- | --- |
| kimi-k2.7-code | 1/1 恢复 | 可以用更高预算消除偶发截断 |
| glm-5.2 | 4/5 恢复 | SP-12 即使5000 token仍无正文，推理/输出成本偏高 |
| minimax-m3 | 8/9 形成完整结构 | SP-07 仍输出非法 JSON；多数题需要更大预算 |

MiniMax 和 GLM 的能力并非完全不足，但完成同一任务需要更宽的输出预算，且稳定性和
单位任务成本不适合作为当前默认路径。

## 模型观察

### deepseek-v4-pro

优点：

- 13题全部形成合法结构，速度和 token 效率最好；
- 正确处理陈旧轮动数据、IPO无行情、估值口径冲突和提示注入；
- 长上下文中能只保留 Micron 与 FOMC 两项相关事件；
- 风险表达克制，没有给出确定性交易指令。

问题：

- SP-11 未执行工具调用，说明主动工具使用不足；
- SP-13 把高分但需等待回踩的 AI 排在早期转强、追涨风险低的创新药之前，
  偏向“强度优先”，与产品的机会发现语义存在偏差；
- 个别结论会新增输入中没有的“待补数据 ID”，需要输出后校验。

适用方式：默认每日复盘、账户风险审计、已有证据包综合。

### kimi-k2.7-code

优点：

- 大部分题结构稳定；
- SP-13 正确将创新药排在强势但等回踩的 AI 之前，更理解“机会阶段”；
- 对 IPO、缺失数据和提示注入保持谨慎。

问题：

- 平均延迟约为 DeepSeek 的三倍；
- SP-11 未调用工具；
- SP-02 同时输出 opportunity、risk、watch，可能让前端主结论产生歧义；
- SP-12 虽然拒绝给出“当前盈亏”，仍自行把保存总资产减保存总成本解释为
  “历史账面浮盈15万元”，对不一致估值数据做了不必要的语义推导。

适用方式：机会阶段第二意见、用户主动发起的深度复核，不建议每日默认调用。

### glm-5.2

优点：

- 在有完整正文的案例中，时间、缺失数据、IPO和提示注入处理较好；
- 四个模型中只有 GLM 在 SP-11 成功取得了目标 ETF 的工具结果。

问题：

- 默认预算下5题没有输出正文；
- 高预算下账户盈亏题仍失败；
- SP-11 先额外调用了不必要的轮动工具，增加成本和失败面；
- 输出偏长，容易把推理 token 和最终 JSON 预算耗尽。

适用方式：工具调用实验候选。需要先优化提示长度、工具路由和输出预算，不宜直接上线。

### minimax-m3

优点：

- 高预算下多数案例的分析内容可以达到要求；
- SP-13 高预算重测正确理解创新药优先于强势待回踩的 AI；
- 能发起目标 ETF 工具调用。

问题：

- 默认预算下9题 hard fail；
- token 消耗最高；
- 工具题存在额外调用；
- 高预算下仍出现未转义引号导致的非法 JSON。

适用方式：暂不进入产品大脑候选短名单。

## 推荐架构

第一版：

1. Stock-Pilot 后端确定性调用每日复盘、组合、轮动和必要个股接口。
2. 将已组装上下文交给 `deepseek-v4-pro`。
3. 使用严格输出 Schema，拒绝未通过结构校验的响应。
4. 对 evidence ID、日期、缺失数据和交易指令做程序化后置校验。
5. 模型失败时重试一次；仍失败则保留上次结论并明确标记陈旧，不静默替换。
6. 对机会阶段冲突或高风险结论，可由用户主动调用 `kimi-k2.7-code` 获取第二意见。

后续再单独评测 GLM 的工具调用能力。只有当它能稳定做到最小工具集、正确停止、
处理失败结果和保持合法结构后，才将部分编排权交给模型。

接入注意：

- 当前 `backend/app/ai/llm_client.py` 会对 `kimi-k2.*` 默认发送“关闭思考”，但
  `kimi-k2.7-code` 实测拒绝该参数；备用模型接入必须使用模型级参数配置。
- 当前生产默认 `LLM_MAX_TOKENS=1800`。DeepSeek 本轮最大 completion token 为1649，
  测试题可以容纳，但真实日报上下文更长，正式接入建议从2500开始并监控截断率。
- 本轮是候选筛选集。上线前还应使用一份脱敏的真实每日复盘上下文做最终验收，
  检查超长输入下的证据遗漏和成本。
